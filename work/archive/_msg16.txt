## 一、需求澄清与方向纠正（重要）
用户明确：这个游戏是给**两个人异地各用一台设备**玩的，所以启动与联机都必须围绕异地场景。
因此删除了此前做的局域网版启动脚本（4 个），改为以**公网隧道**为主线：

- 删除：`启动五子棋.bat/.ps1`、`启动联网版.bat/.ps1`（局域网 IP + 防火墙 + 本机地址那套）
- 新增：`启动异地联机.bat` / `启动异地联机.ps1`

### 新增脚本做的事（每步都针对一个真实的异地障碍）
1. 检查 Node.js；
2. 检查内网穿透工具 cpolar（异地必须；未装/未登录给出具体命令）；
3. 启动游戏服务器——**端口自动从 `cpolar.yml` 的命名隧道配置读取并对齐**
   （用户的 `gomoku` 隧道写死 `addr: "8123"`；若服务器监听别的端口，隧道会把请求转到空端口，
   表现为“公网地址打不开”）；
4. 启动隧道并从输出中抓取公网地址（**优先 https**，因为异地的语音/视频通话需要安全上下文）；
5. 用真实请求确认公网地址可访问；
6. 打印公网地址并在终端打出**二维码**（复用页面内嵌 QR 编码器，零依赖）；
7. 用**公网地址**打开浏览器——这点关键：邀请链接是“当前页面地址 + ?room=房间号”，
   用 127.0.0.1 打开时生成的是本机链接，异地对方打不开。

### 实测验证（公网链路）
- 隧道建立成功并获得公网地址（如 `https://xxxx.r16.vip.cpolar.cn`）；
- **公网 HTTP**：页面 140.9KB、`/engine/gomoku-ai.js` 137.6KB 均 200；
- **公网 WebSocket**（异地实时对战的关键，用 `work/verify-public-tunnel.js` 实测）：
  建房 → 对方加入 → 双向落子同步 → 服务端权威拒绝非法落子 → 聊天转发，全部通过；
- 修复了一处自造 bug：从 cpolar 日志抓 URL 时把结尾引号也吞了进去，
  生成 `https://xxx.cpolar.cn"` 这种坏链接（二维码/链接都会失效），已加正则与二次裁剪。

## 二、修复强度改造留下的半成品引擎（关键）
工作区里的引擎有 389 行未完成改造（增量棋型引擎 + 静止搜索 + 深搜 + 走法池 + TT 代龄），
但**跑不起来**，多个测试同时失败。逐层查清并修复：

1. **状态声明缺失**：模块函数引用了 `spaceSum / evalReady / cgFive / cgLv / boardHashLo / ttGen /
   candScratch / scoreScratch` 等新增状态，但声明只在模板里、没进模块 →
   `xxx is not defined`。→ 统一把模板状态段并入模块，并补齐模块独缺的声明。
2. **生成器不输出状态段**（根因）：`build-engine.js` 只搬运常量/函数/开局库，
   状态段用的是模板里那份旧内容 → 每次生成都会丢掉新增状态。→ 让状态段也从模块抽取回填，
   并加“声明完整性”自检。
3. **对外接口退化成裸函数**（最隐蔽）：模板接口本来写的是 `publicFn(...)` 包装
   （页面/测试会**直接改写 AI.board**，需借此同步增量棋型状态），但模块里是裸函数引用 →
   外部改盘后读到过期缓存，**所有局面都返回同一个点 (10,3)**。
   → 从模板同步接口段，并在生成流程中保留。判定实验：补上包装后 3/3 失败局面立刻正常。
4. **生成器自身不再幂等**：注释被反复搬进产物，每跑一次多几行。
   → 抽取状态段时跳过说明性注释，并明确“模板占位符处不得再写声明或注释”。

修复后：生成器自检通过、**幂等**（二次运行“完全一致”）、引擎可加载。
